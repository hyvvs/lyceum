# Lyceum UI fidelity loop

**Owner-approved Today is frozen.** All remaining components/screens must be more refined and premium, not simpler. The new owner-controlled rules and rubric in `docs/20-ui-fidelity-brief.md` take precedence over old reference language, source screenshots and historical task order. Never import auxiliary component-look CSS.

1. **Look first.** View `docs/design-reference/reference-home.png`, `reference-messages.png`, `reference-saved.png`, `reference-transition.png`, and `comparison-today-vs-reference.png`. If you cannot view images, say so and stop. Read `docs/20-ui-fidelity-brief.md` fully, then `docs/18-design-language-glass.md` and `packages/ui/src/glass.css` and `motion.ts`.
2. **Inventory and prerequisite checks.** List all remaining old UI/fixture files; classify each as rework/wire, dev-only gated, or delete. Keep the approved Cole backdrop and create a **luminous warm-to-cool light field behind glass**, not a replacement photo. Verify copyright and contrast. Freeze Today.
3. **Material/component and behavior checklist.** Every surface and control uses the **same depth-tiered glass** (gradient rim, inner highlight/glow, grain and soft cast depth, never flat navy/black slabs); proper fallback remains polished. Blue only primary action, learner bubble and one highlighted data bar; other color only meaningful tints/status. One shared type/icon scale, numbers and labels paired in one line, matching heights and gutters, less than ~25% empty area. Proper concentric rounded softly glowing mastery ring and gradient chart bars with faint gridlines. Role-specific primary/secondary/tertiary/icon actions, `motion.ts` presets for lifts/entrance and reduced-motion variants. No visible banned scaffolding words from the brief. The **single `Demo data` chip** is the only environment marker; never fabricate real learner progress. Every visible control actually works; hide unfinished features. Implement screens **only in `apps/web` using `@lyceum/ui` real primitives**, not fixture clones.
4. **Capture from the actual application.** Build production fresh; screenshot **1440×900 from a launched production route after each screen** (never call a disconnected fixture a production screen), plus hover/mobile/contrast where useful. Capture interaction and motion at real rate, not only animation-disabled stills. For a shared-components-only round, gather real component interaction and visual evidence without adding a fake user-facing gallery route.
5. **Compare.** Put each screenshot beside the matching reference crop. Score the 10-point rubric in the brief section 6 (0 to 2 each) with one line of evidence per criterion. List the top five visible differences.
6. **Wire and test.** One Playwright test per real route must **activate every visible interactive element and assert meaningful behavior/no errors**; axe, keyboard, 200%-text, RTL, reduced-motion/transparency, high-contrast, empty and error checks. Run `pnpm verify` and a current production build. No dead buttons or inactive tabs, and no old UI sitting unused.
7. **Fix and repeat** up to three rounds, re-capturing each time. Stop visual iteration only at ≥17/20 with no zeros; this self-score is **not** owner approval. Ask a read-only `lyceum-ux-review` to inspect the diff, real pixels and behavior.
8. **Report and pause.** Attach before/after images and actual production route screenshots for screen rounds, score and top five differences, list inventory decisions, test output, outstanding limits. Run the `lyceum-handoff` skill **every round**, commit/update `docs/STATUS.md`, and **stop until the owner approves**. Exact round order: **shared components → Study session → Sources → Plan → Models → Settings → Practice**; never build two screens in one round.

Hard rules: never use assets from the reference video; never show developer scaffolding or more than one `Demo data` chip; never use opaque reading-tier panels for entire dashboards; don't remove Today; never substitute flat solid material in ordinary views; don't show controls for unimplemented features. The owner approval barrier is mandatory.
