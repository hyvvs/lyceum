# ADR-0010: M0-004 local-first web shell bootstrap

- Status: accepted
- Date: 2026-11-25
- Accepted: 2026-11-25 (Independent Audit #22)
- Deciders: project owner (Audit #20 implementation scope A–D; Audit #21 remediation experiment; Audit #22 explicit architecture and temporary override acceptance)

## Context

M0-004 is the first **real browser application** over the previously merged seven primitive families. The approved [M0-003 sequencing exception](../qa/m0-003-exit-decision-2026-11-24.md) permits M0-004 **development and draft-PR verification only** despite M0-003 remaining `[~]`; it does not waive manual AT, native Windows forced-colors, applicable axe `incomplete`, WCAG 2.2 AA or release/merge gates. The original [web shell task card](../../tasks/M0-foundations.md) requires a real Vite/React/TanStack Router entry, offline installable PWA, worker bootstrap/cancellation, accessible error boundary, theme, browser tests and measured Lighthouse. Architecture remains local-first, with no invented learner progress or provider integration.

## Options considered

1. **Owner-approved Vite + typed TanStack Router + i18next/ICU; native Web Worker and generated PWA (chosen for the draft):** meets required tooling and typed navigation, uses the smallest app-private worker contract without Comlink, offers generated static cache revisions. Costs: build-time Workbox tree, new package/license/security review, and testing of SW updates.
2. **No router/PWA plugin, handwritten history/SW:** fewer dependencies but violates the declared router architecture and increases offline update/cache invalidation risk. Not adopted.
3. **Comlink or a shared cross-package worker API:** more indirection before a real tutoring engine consumer, contrary to owner limit. Not adopted.

## Decision

Independent Audit #20 explicitly authorized these **exact runtime pins** in `apps/web`: `react@19.3.1`, `react-dom@19.3.1`, `@lyceum/ui@workspace:*`, `@tanstack/react-router@1.170.46`, `i18next@27.2.7`, `react-i18next@18.0.3`, `i18next-icu@2.7.1`, **`intl-messageformat@12.1.4` (corrected from 12.2.1)** and `zod@4.6.7`. Build tools `vite@8.3.8`, `@vitejs/plugin-react@6.3.0`, `vite-plugin-pwa@2.0.0`, existing TypeScript `5.9.3` and existing React type versions may be reused. Exact registry versions, licenses, peers and Node 22.20.0/pnpm 9.15.0 compatibility were confirmed before installation; no other runtime package was added.

The browser app has typed `/` and `/settings` routes, English/Spanish ICU strings with English fallback, validated device-local theme/language/transparency preferences, early paint application on `document.documentElement` (including independently portalled controls), native focus/landmarks and truthful not-configured surfaces. App-only worker messaging is a versioned Zod-checked `probe/cancel/ready/cancelled/error` diagnostic transport; **it is not a tutor, mastery engine, storage protocol or public `@lyceum` contract**. PWA manifest and SW are generated with a bounded static app-shell precache and no runtime caching of learner or remote data; update activation is user-controlled to avoid surprise reloads. The app uses a **temporary original CSS-generated backdrop** only, pending M0-019. The full V5 visual comparison, motion work, licensed imagery/rendered-pixel contrast and target WebView performance remain independently gated M0-017–M0-020 work.

## Consequences and initial Audit #20 security limitation (historical; resolved under Audit #21)

- Positive: real accessible and keyboard-operable routes, local themes and localization, repeatable worker cancellation, production offline reload, measured app bundle and browser/a11y gates without changing `packages/core` or `packages/ui` exports. Existing Storybook gate remains intact.
- **HISTORICAL FAILURE (pre-remediation):** the initially approved `vite-plugin-pwa@2.0.0` resolved `workbox-build@7.4.1` → `glob@11.1.0` → `minimatch@10.2.6`. At that earlier head, unrestricted `pnpm audit` reported **two moderate vulnerabilities**: [GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) and [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249). Patched glob **>=14.0.2** was outside Workbox's `^11` range, and patched minimatch **>=11.0.1** was outside glob11's `^10` range. No override or audit waiver existed **at that time**; the red audit blocked merging. **This is a historical record, not the current installed dependency or audit status; see Audits #21 and #22 below.**
- Manual screen-reader/Windows native forced colors and relevant axe `incomplete` dispositions are **NOT RUN**, not replaced by Chromium emulation/automation. M0-003 remains `[~]`; M0-004 is `[~]` while implementation is in progress.
- Under Audit #20 alone, no M0-004 merge, public release, certification, M0-005 or M0-017+ implementation was authorized. Audit #22 subsequently authorized a **controlled pre-release foundation merge only**, subject to fresh exact-head checks; it did **not** complete M0-003 or M0-004, authorize public release, or permit dependent milestones.

**Revisit triggers:** at M0-004 acceptance/merge decision, at manual M0-003 accessibility signoff, before any public release, or when Workbox/peer/security advisories change. Confirmed supported-consumer accessibility defects require focused fixes and regression tests.

## Independent Audit #21 — narrow Workbox remediation evidence (originally proposed; accepted under Audit #22)

The project owner separately authorized **only a reversible security-remediation experiment**, not approval of this ADR, milestone acceptance, additional dependency changes, audit suppression or PR merge. On 2026-11-25 the official npm workbox-build latest remained **7.4.1** and still declared glob **^11.0.1**, so there was no supported upstream patched release covering both advisories. The initial Audit #20 red-audit state above is retained as historical context.

The experiment applies a **single exact parent-scoped pnpm selector**, **workbox-build@7.4.1>glob = 14.0.3**, keeping vite-plugin-pwa 2.0.0 and workbox-build 7.4.1. Its actual resolved dependency is **minimatch 11.0.9**, with path-scurry 3.0.0 and @isaacs/nonrecursive-glob-match 1.1.0; no separate minimatch override. All new packages have permissive OSI-approved BlueOak-1.0.0 licenses, support the declared Node/pnpm toolchain, and introduce no install/postinstall hooks. Unrestricted local pnpm audit returns **zero known vulnerabilities** with no exceptions. This crosses Workbox's declared glob major range deliberately and is **not upstream-supported** merely because the build and audit pass.

Regression evidence: frozen install, full unit/type/lint and existing Storybook/88-browser/141-story/164-state axe gates, real application 12 Chromium tests plus one optional screenshot skip, exact resolved Workbox glob module test, nested static-file/hidden/ignore/revision fixture, actual offline startup/reload and opt-in A-to-B service-worker update all passed. The generated SW SHA-256 and static precache URLs/revisions are **byte-identical** to the pre-override artifact; initial route **163,371 B gzip** and with worker **187,458 B** remain unchanged. Desktop/simulated-mobile Lighthouse Performance and Accessibility are both **100/100** on the local production shell, not native device or WCAG proof. App privacy/cache and CSP config, architecture and visuals were not changed. See the [scoped Audit #21 evidence and limits](../qa/m0-004-workbox-override-audit21-2026-11-25.md), plus the latest exact-head hosted checks on [DRAFT PR #18](https://github.com/hyvvs/lyceum/pull/18).

**Remaining risk and removal trigger:** Workbox 7.4.1 calls the compatible globSync surface, but an out-of-range major override can still differ on untested paths/OS builds. After an officially supported Workbox dependency release resolves both advisories, remove this override in a separately reviewed change only after repeated audit/precache/offline/update/accessibility/CI checks. Current source has no private emitted assets; a future public-dist private JS file could match the inherited broad static glob and must be prevented by future feature-specific privacy review. Manual native assistive-technology, Windows forced colors and applicable axe incomplete remain **NOT RUN**, M0-003/M0-004 **in progress**, M0-017–M0-020 future. This paragraph records the **Audit #21 state before later Audit #22 acceptance**, not an ongoing prohibition on the specifically authorized conditional merge.

## Independent Audit #22 — accepted decision (2026-11-25)

The project owner **ACCEPTED ADR-0010** for the M0-004 **pre-release browser shell only**: typed TanStack Router `/` and `/settings`; validated device-local preferences; English/Spanish i18next/ICU with explicit fallback; the Zod-validated **app-private** native diagnostic worker (not a tutor or public protocol); static-only generated PWA; opt-in service-worker updates; strict same-origin CSP; and truthful empty/not-configured states. The original CSS atmospheric backdrop is explicitly **temporary**. This is architectural acceptance, not M0-004 milestone completion or a WCAG 2.2 AA claim.

**Exact owner-approved temporary root pnpm override:**

```json
"workbox-build@7.4.1>glob": "14.0.3"
```

The approval applies **only** to the tested `vite-plugin-pwa@2.0.0` → `workbox-build@7.4.1` → `glob@14.0.3` → `minimatch@11.0.9` chain and current build. **Accepted residual risk:** Workbox declares the older glob `^11.0.1` semver range; glob 14 is a deliberate out-of-range major override, despite successful CommonJS `globSync` compatibility, identical generated service-worker bytes, bounded static asset inventory, real offline routes and user-consented A-to-B update. This is **not** blanket approval for major overrides or additional pnpm substitutions; no audit exception/suppression is permitted.

**Mandatory override removal trigger:** when an **officially compatible and patched Workbox dependency** resolves both advisories, propose removal in its own reviewed change. Before merging that change, rerun frozen installation, unrestricted `pnpm audit`, lockfile/module resolution, precache and privacy comparison, actual offline navigation/reloads, user-controlled service-worker A-to-B update, full unit/Storybook/keyboard/axe/production web suite and all three hosted CI jobs. Do not silently remove or replace the override.

**Accepted verification evidence:** PR #18 at reviewed head `ccc257de553fc628f6a08263c500e18b7355e705`, [GitHub Actions run 45526127968](https://github.com/hyvvs/lyceum/actions/runs/45526127968) **SUCCESS** on Verify, **unrestricted Dependency audit (zero known vulnerabilities)** and Secret scan; Linux 107/107 unit tests, 88/88 Chromium, `AXE_COVERAGE_VERIFIED unique_stories=141 required_states=164 executed_states=164`, and 12/12 production web tests (one optional screenshot-only skip). Generated SW and precache match the tested pre-override baseline; bundle initial route 163,371 B gzip (worker-inclusive 187,458 B). Independent architecture, security and UX/accessibility reviews were **read-only**, not formal GitHub reviews. The owner separately **authorized PR #18's controlled squash merge only after** a documentation-only acceptance amendment and fresh full exact-head CI green. Zero formal submitted reviews are accepted **for PR #18 only**. The new doc head and actual squash/main CI must be verified before calling that merge executed.

**Unchanged manual, design and release gates:** M0-003 `[~]` and M0-004 `[~]`; actual supported screen-reader, native Windows forced-colors and applicable manual axe `incomplete` signoffs **NOT RUN** (see [human execution handoff](../qa/m0-004-manual-accessibility-handoff-2026-11-25.md)); bounded reading-and-controls Dialog only and ADR-0009's accepted **FocusScope deferral**, never arbitrary unbounded Dialog certification. The fixed mobile dock may obscure **unfocused** reading text at intermediate scroll offsets; the first genuine reading-intensive consumer requires visibility, Tab/Shift+Tab focus and bottom-safe-area tests. Full distinctive Glassy Dashboard V5-inspired composition (M0-017), spring motion (M0-018), original/licensed atmosphere and rendered-pixel contrast (M0-019), and native supported WebView performance (M0-020) remain separate required milestones. No M0-005/later development, deployment, public release or WCAG certification was authorized.
