## Honest visual comparison with internal V5 Home / Saved frames

Side-by-side design reading of the **real** Slice A screenshots against the internal supplied V5 Home/Saved contact frames, which must not be copied, embedded or distributed:

- **Recognizably V5-inspired:** floating central glass pill, vertical icon dock, dark translucent surfaces with fine rims and inner highlights, graduated elevations, proportionally varied overview/feature/reading cards, five separate blue/amber/purple/green/red frosted category treatments and one saturated blue CTA. The CSS backdrop introduces warm amber against cooler indigo with a schematic horizon/window geometry.
- **Not a V5 replica:** supplied V5 has natural photographic atmosphere, convincing deep environmental diffusion, tiny stats, bar/graph detail and more photographic light interplay. Slice A substitutes **original abstract CSS geometry**, honest unconfigured labels and decorative non-data bars. Its window lines are stronger and headline/empty copy larger than V5; glass diffusion is visually recognizable but the ambiance is less natural. This visual-prototype limitation is not cured by green computed-filter or axe tests.
- **Reading/solid fallback:** near-opaque `GlassPanel level="reading"` separates explanatory copy from scenery. Explicit reduced, opaque and high-contrast versions remove blur and use deliberate solid hierarchy; the fallback must be evaluated as its own finished composition, not as a transparent-mode screenshot with blur disabled.
- **Mobile:** no matching V5 mobile screenshot was supplied; 390-wide bottom dock is an original adaptation. On very short 320×256 screens **or with 200% root text**, the dock is moved below the initial viewport to protect reading/heading content. Full-page screenshots and focus/scroll checks help assess obstruction, but the first real reading-intensive consumer still requires separate manual scroll/focus/safe-area acceptance.
- **Axe limitations:** automated WCAG A/AA scans execute for all stories, but translucent gradient `color-contrast` can be `incomplete`; no inference of contrast PASS from that status. M0-019 rendered-pixel sampling and genuine human tests remain future requirements.

## Test, review and risk boundaries

- **Observed final local gates (Windows 11 / pinned pnpm):** frozen `corepack pnpm install --frozen-lockfile` PASSED; `corepack pnpm verify` PASSED (110 unit tests, one preexisting expected platform skip, boundaries/agentcheck/typecheck/lint); `corepack pnpm audit` ran **without any restriction** and reported **“No known vulnerabilities found”**; Storybook build PASSED; `corepack pnpm test:ui` PASSED **98/98 Chromium tests** including integrated visual modes; production `web:build` PASSED; production `test:web` PASSED **12/12 cases** with one optional screenshot-only skip. Recheck these on exact final PR HEAD in hosted CI; this local run alone is not hosted evidence.
- Primitive inventory: original seven families / **141 stories** preserved, plus **56** stories across `GlassPanel` (19), `GlassCard` (17), `TintCard` (20), for **197 distinct primitive stories and 220 required/executed axe states**, observed in the full-suite `AXE_COVERAGE_VERIFIED` reporter. Eight integrated composition exports live outside that primitive inventory and are separately enumerated against their source and each scanned with real Chromium axe (no known violations; documented `incomplete` rules remain).
- Full-glass scene tests count at most six concurrently blurred surfaces (current design target five), reject nested backdrop-filter ancestors, verify named navigation and non-color labels, 44px visible controls, keyboard focus, RTL dock gutter, responsive/short widths and true 200% **root text**. The CDP 2× **pinch visual viewport scale** test is separate; it is **not a native Chrome page-zoom test**.
- **Outstanding native zoom gate:** a headless Chromium `Ctrl+NumpadAdd` attempt left `innerWidth` 1440 and `devicePixelRatio` 1 unchanged. Genuine browser UI page zoom is therefore **NOT VERIFIED**, not a PASS, and needs a separate supported real-browser execution before final acceptance. Do not rename or treat CDP pinch or CSS root scaling as browser zoom.
- **Independent read-only reviews:** architecture found a narrow-type `includes(string)` check, missing source-index composition reconciliation, overly narrow keyboard checks and possible nested blur; all were strengthened. Accessibility found wrong physical RTL dock positioning, fragment-nav `aria-current="page"`, incomplete focus/44px/short-viewport evidence and an opaque-vs-incomplete evidence distinction; code now uses logical dock placement, hash-synchronized `aria-current="location"`, broader geometry and real Tab/Shift+Tab coverage and adaptive short-height dock. Security found no confirmed blocker in inspected changes; Storybook-only import of an existing app Icon is a noted fixture boundary, and exact hosted secret/dependency scans are still required. **Independent visual reviewer explicitly viewed the real V5 closeups and five actual Slice A PNGs** (not source alone), judging the direction recognizable for a *draft prototype*, **not final fidelity acceptance**. They flagged a mobile 200%-text dock obscuring an unfocused first card, abrupt backdrop window lines and desktop hero sizing that hid most tinted cards. Follow-up code makes the 200%-text dock non-overlaying, softens the structural lines and reduces heading space; full-page desktop/opaque evidence is added. These corrections require visual reinspection of their final captures; no fictional approval is inferred.
- No public `PillNav`/`Dock`, RoundIconButton, StatCard, BarChart, ChatBubble, MasteryRing or SegmentedControl, new runtime dependency, new font/image asset, production app edit, shadow learner data, new animation, native AT signoff or updated ADR is part of Slice A.
