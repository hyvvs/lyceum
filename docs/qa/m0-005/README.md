## Behavior and trust boundaries actually implemented

- Real Tauri v2 release executable wraps the **existing** web app. Bundled and development origins are checked in **both** navigation and registered Rust IPC paths; untrusted child windows denied, no Tauri plugins or additional capability permissions. Desktop-only Vite CSP allows narrowly `ipc:` and `http://ipc.localhost`; ordinary browser/PWA CSP remains unchanged. The WebView's existing theme, routing and native worker are retained. Desktop bundles omit PWA manifest/service-worker artifacts and do not register a service worker, avoiding stale cached assets in a persistent WebView profile. The read-only IPC handshake waits for the bundled document load event and retries only the local readiness command (3 attempts, 50 ms apart); it writes only `data-desktop-ipc="ready|unavailable"`, never a native path or error message.
- Windows WebView2 now installs a request-egress guard before navigating the hidden `about:blank` bootstrap to the bundled app. It requires `ICoreWebView2_22` and registers HTTP and HTTPS wildcard filters with `COREWEBVIEW2_WEB_RESOURCE_REQUEST_SOURCE_KINDS_ALL`; interface/query/filter failure aborts startup, with no legacy-filter fallback. Disallowed HTTP(S) requests receive a synthetic 403. Wry 0.57.4's Windows custom-protocol workaround maps `tauri://localhost` / `ipc://localhost/{command}` to HTTP virtual-host-shaped URLs; source inspection confirms the app uses the custom-protocol handler path, not `SetVirtualHostNameToFolderMapping`.
- Windows IPC exception is limited to `http://ipc.localhost:80` FETCH requests using POST or OPTIONS and exactly one nonempty encoded command path segment, with no userinfo, query or fragment and no encoded slash/backslash. This variable path is required by Tauri 2.12.7: command names (including `plugin:__TAURI_CHANNEL__|fetch`) are encoded into the path; there is no fixed `/__invoke` endpoint. Other resource contexts and methods are denied. The renderer's registered-command checks remain an additional boundary.
- Win/mac OS keyring stores bounded synthetic/API credentials. JavaScript has scoped set/has/delete, but not plaintext get: `credential_get_native` is intentionally **Rust-only**. No credentials reach provider calls, renderer output, logs or app data files. Linux has no enabled backend and rejects operations. There is no account access.
- Native HTTP accepts `destinationId`, fixed GET / future narrowly configured POST and synthetic request ID (cancel supported), not URL/headers/provider keys from renderer. Exactly **one** bundled documentation-only origin `https://example.com/`, GET-only, no automatic requests; other/unconfigured destinations denied. Exact URL approval, public-IP DNS validation plus request pinning, TLS hostname checks, no redirects/proxy, strict body/response/concurrency/timeout limits; no live provider requests, local endpoint enablement or model interaction.
- Native directory command uses the resolved OS app-data directory and returns only unit readiness over IPC (no user/profile path enters JavaScript). It creates only its final component; on a fresh macOS profile it can safely create the standard Application Support parent only beneath an existing non-symlink `~/Library`; Windows requires its OS-provided `%APPDATA%` parent. It rejects files, symlinks and Windows reparse points, atomically creates new Unix leaves with mode `0700`, and fails closed on an existing broader-permission Unix directory instead of chmod'ing a pathname. Windows inherits the OS per-user profile DACL; hosted CI checks the new directory owner, inheritance and allow ACEs for enumerated common machine-wide/logon, service and application-package identities (including package-specific AppContainer SIDs), not every possible local group. This is not an unrestricted filesystem bridge. A future SQLite adapter still needs handle-based/no-follow database-file opens and its own ACL/TOCTOU review.

## Current Windows request-egress follow-up — local, uncommitted evidence

This follow-up is being developed on top of reviewed base HEAD `3134e7ffb657a06652959caf05816be3379c2451`; it is not yet committed or hosted-verified.

- The WebView2 guard requires the API22 interface at runtime. An older WebView2 Runtime that does not expose `ICoreWebView2_22` will fail closed during startup; no incomplete legacy filter is installed. A minimum supported runtime/update policy still needs to be made explicit before release.
- The Tauri IPC route was checked against pinned Tauri `2.12.7` and Wry `0.57.4` source. Tauri invokes `ipc://localhost/{encoded-command}` with POST; channel fetch is the ordinary command `plugin:__TAURI_CHANNEL__|fetch`. Wry's Windows custom-protocol workaround maps this to `http://ipc.localhost/{encoded-command}`. The guard therefore allows only FETCH context, POST/OPTIONS, one nonempty encoded command segment, and exact HTTP host/port; it does not permit arbitrary images/scripts/media or arbitrary methods on the IPC origin.
- `NavigationStarting` cancellation alone is not request containment: WebView2 may issue an HTTP GET while the host handles the navigation event. The request guard is the separate control that returns 403 before an unapproved HTTP(S) request reaches its destination.
- Wry's pinned Windows path was inspected: it registers custom-protocol handlers and uses the HTTP workaround; it does not use `SetVirtualHostNameToFolderMapping` for this app origin. The virtual-host-folder-mapping caveat is therefore not a demonstrated bypass for this implementation.
- Latest local packaged Windows smoke launches the actual release executable. It verifies real IPC/keychain/app-data behavior, remote fetch/script/image requests, a blob worker's remote fetch, and a real loopback HTTP 302 redirect. The redirect source receives exactly one GET; CDP observes the redirected fetch to the untrusted target, the guard emits the blocked marker, and the sentinel server receives **zero** target requests. The top-level remote navigation is also denied and the window remains on `http://tauri.localhost`; no popup is created. The smoke attempted a cross-origin iframe but did not observe an iframe request, so iframe behavior is **not** claimed as runtime-verified by this result.
- The redirect source exception is test-only and compile-time gated behind Cargo feature `native-smoke`; the native CI smoke build enables it through `build:native-smoke`, while the ordinary `build` command excludes it. The WebView2 CDP remote-debugging arguments, isolated smoke profile, synthetic keychain roundtrip and smoke markers are also compile-time gated; inherited environment variables cannot enable them in an ordinary production build. The redirect exception additionally requires `LYCEUM_DESKTOP_IPC_SMOKE`, an exact ephemeral loopback URL supplied by the harness, GET and FETCH/XMLHTTP request context. The redirect target is never allowlisted. It exercises a real HTTP server 302 and the redirected WebView2 request path. The source is the exact loopback smoke endpoint, not the bundled `tauri.localhost` origin.
- After the feature-enabled packaged smoke passed, the ordinary feature-off production executable was rebuilt. A binary-string check confirmed it contains none of `LYCEUM_DESKTOP_IPC_SMOKE`, the WebView2 CDP port/redirect-source variables, the remote-debugging-port argument, or the synthetic native IPC marker (`productionSmokeFeatureAbsent=PASS`). Native CI now repeats this ordinary production packaging and marker-exclusion check after the feature-enabled smoke on both Windows and macOS.
- Request metadata extraction errors (`Request`, URI, method or resource context) take the deny path and attempt a synthetic 403. If response creation or `SetResponse` fails, the app exits with failure rather than returning a COM callback error and continuing without an explicit deny response.
- **Boundary:** this is HTTP(S) WebView request filtering, not a complete renderer network firewall or filesystem sandbox. No `file://` filter is installed. WebSocket, WebRTC/ICE and other non-HTTP(S) channels are not established as covered. The existing CSP remains defense-in-depth; do not claim all possible network egress is prevented.
