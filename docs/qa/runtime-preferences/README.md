This controller is scoped only to the QA fixture and adds no runtime Settings UI, new public component API, dependency or focus owner.

`tests/ui/runtime-preferences.spec.ts` asserts the original Dialog trigger → active Dialog → separately portalled Select is keyboard-opened; Physics is chosen and retained across every change; the same DOM node handles for Dialog, Select trigger and **open portalled popup** remain connected, the fixture's React instance ID is unchanged, and the Select stays focusable, active and correctly `aria-expanded` with no hidden/inert ancestor. Live changes are **dark → light → dark**, **standard → high contrast → standard**, **full → reduced → off → full transparency**, and **full → reduced → off motion**. Computed popup background and text colors change with theme; `backdrop-filter: blur(32px)` is observed for full glass and becomes `none` in reduced/off/high contrast; computed `--motion-slow` is `.45s`, `.15s`, then `0s`. A real keyboard ArrowDown/Up still works, Escape restores focus Select → Select trigger, then Escape restores focus Dialog → its original trigger. After closing, no modal-owned `data-aria-hidden` or `inert` remains. Storybook's own persistent hidden addon documentation/vision-filter elements are **not** confused with abandoned modal locks.

At **320×256 with real 32px root text (200%)**, the already-open popup stays the exact same node, visible inside viewport bounds, keyboard-operable and without horizontal document overflow. Chromium `forcedColors: active` and `reducedMotion: reduce` are **jointly emulated** during the same mounted popup; the computed surface becomes solid and the effective base motion token is `0s`. The popup remains selected/focused until Escape and the final close restores focus without stale modal locks. A further test rejects malformed inherited preference keys and proves the QA fixture restores its original Storybook globals upon an actual React unmount without a page reload. The installed five WCAG A/AA tags (`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`) run via the same axe helper at **17 checkpoints** (initial + ten changes + two closes + three narrow/OS checkpoints + after test-only unmount). The new test-only QA story does **not** change the existing **141/141 primitive IDs and 164/164 story-state** gate.
