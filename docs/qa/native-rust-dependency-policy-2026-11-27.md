## Mozilla MPL-2.0 obligations — before any distributable installer

Official authority: [Mozilla MPL-2.0 license](https://www.mozilla.org/en-US/MPL/2.0/) §§1.4, 1.10, 1.13, 2.1–2.3 and 3.1–3.4; [Mozilla's MPL FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/). MPL-2.0 is **file-level weak copyleft, not permissive**. Distributing covered software in executable form requires providing the corresponding MPL-covered source (including covered modifications and any files containing covered code) and timely, reasonable recipient access at no more than source-distribution cost, with notices and no additional restrictions on source-form rights. Independently authored Lyceum files that contain **no** MPL source do **not** automatically become MPL-licensed. Using a build-time library does **not** automatically make generated files MPL; conversely, being build-time or unmodified does **not** excuse actual distributed covered output. Legal classification must follow **real packaging output** and upstream license texts, not assumptions.

## CI and regression criteria

- Normal `corepack pnpm verify` **always** validates the policy manifest, fixed expiry, verified 39-record ancestry snapshot and all mandatory general CI jobs, even on protected main before the desktop Cargo project is merged. Only the **live native Cargo/target graph** portion is inactive when **none** of Cargo.toml/Cargo.lock/deny.toml exist; a **partial** native project fails closed. Missing policy files, altered ledger or an absent general CI workflow fail rather than bypass the rule.
- The guard checks exactly seven crate/version identities and matching crates.io checksums, reviewed immediate-parent relations/intermediates, no extra versions; validates that cargo-deny allows only permissive global licenses with seven exact-version MPL exceptions; preserves all-dev/build coverage, all-target analysis, unknown Git/registry denial, and the one specifically authorized advisory ID.
- The existing general **Dependency audit** job retains **unrestricted `pnpm audit`** and, when Cargo files exist, additionally installs pinned `cargo-audit 0.23.0`/`cargo-deny 0.19.9`, performs full lockfile `cargo audit --file ...` **without any ignore flags**, all-platform `cargo fetch --locked`, runs `cargo deny check licenses advisories sources`, then the live guard (which validates both tools' advisory snapshots and real target graphs). Source/step/conditional/failure-propagation regression tests reject disabled or nonblocking security jobs and steps. The desktop-native workflow is introduced only in **PR #31**, not on protected main; before PR #31 can pass `pnpm verify` it must also wire the same live guard, without removing its Windows/macOS tests or all-target Rust policy job. This separation is intentional, not a waiver of its integration.
- Tests must show that an eighth MPL package, unauthorized version, unexpected source/checksum/parent, global MPL allow, wildcard license selector, broadened RustSec ignore, unknown registry/Git source or reduced audit graph fails. No `cargo-deny` failure is considered fixed solely because `cargo audit` passed.

The exceptions are reviewed **again by 2027-02-28** or earlier if the pinned Tauri/Wry stack updates, an upstream remediation lands, a crate changes license/source/checksum/dependency paths, Linux/Android support is proposed, advisory classification changes, or packaging/release is contemplated. Owner and supply-chain/security reviewers must approve any new scope through another separate `docs(agents): ...` PR before updates to the desktop policy/config. M0-005 remains incomplete until all real native/hosted and independent acceptance gates pass.
