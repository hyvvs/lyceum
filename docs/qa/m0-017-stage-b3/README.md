## Public API, architecture, routing and desktop duplication

- `packages/ui/src/pill-nav.tsx`: `export type PillNavProps = React.ComponentPropsWithoutRef<"nav">` (imported as `ComponentPropsWithoutRef`); `PillNav = forwardRef<HTMLElement, PillNavProps>(...)`. Renders exactly one named native `<nav>`, forwards native attrs and ref, holds consumer children and existing `glass-float glass-pill` recipe. No links, routing, Tab trapping or current-state logic of its own.
- `packages/ui/src/dock.tsx`: `export type DockProps = React.ComponentPropsWithoutRef<"nav"> & { orientation?: "horizontal" | "vertical" }`; `Dock = forwardRef<HTMLElement, DockProps>(...)`. Same native/ref/consumer-owned semantics; optional `data-orientation` styling hook. App's approved responsive CSS controls actual physical desktop vertical versus mobile horizontal layout, so app does not need to pass a viewport-derived orientation prop. Both minimal exported types/components are re-exported by `packages/ui/src/index.ts`.
- `packages/ui/src/glass.css` adds only existing-token glass/active/hover recipes, logical layout and visible focus via existing consumer styles. No new token names, second glass blur, backdrop asset, font, motion primitive or dependency. The independent architecture review identified app-private CSS selectors in an early draft; they were removed for generic low-specificity `:where(...)` selectors. Real hover/focus interactions exposed a **4.32:1 hovered-link contrast failure**; the hover was corrected with existing solid reading/text tokens and the next full axe inventory passed. Subsequent screenshot review also led to existing-token default link foreground and readable icon glyph sizing in stand-alone stories, without overriding app-specific CSS.
- `apps/web/src/router.tsx` composes real TanStack `Link` children for precisely `/` (Today) and `/settings`, translated labels and consumer-owned `aria-current="page"`, route heading focus, app RTL, distinct named landmarks. The existing B2 `navigation-layout.ts`, dedicated mobile reading scrollport, reserved auxiliary Dock/PWA prompt and measured short-height/200%-root in-flow fallback remain unchanged. Tooltip uses existing `TooltipProvider/TooltipTrigger asChild/TooltipContent` with native anchors; no nested buttons, Tooltip-only accessible names or new public tooltip implementation.
- **Explicit desktop duplication decision:** keep the *visually approved centered PillNav and logical-start vertical Dock* both operable, with distinct named Primary navigation and Quick navigation landmarks and duplicate Today/Settings keyboard stops in documented natural DOM order. Neither visible interactive group is hidden, made `aria-hidden`/inert, removed from keyboard order or given invented routes. A semantic destination redesign requires separate owner permission.
- Initial screenshot-grounded review found the existing Tooltip default top placement masked the reserved mobile reading area. A genuine failing LTR regression captured the overlap; a fixed left side cleared reading but masked navigation in RTL. The **app-private responsive/direction-observing** placement now chooses outward-facing horizontal Tooltip sides on mobile, top on desktop, and a narrow 16px mobile offset, preserving the exported Tooltip recipe. The new test covers **both destinations in LTR and RTL**, reports actual bounding rectangles and rejects overlap with the real reading scrollport, any Dock bounds or viewport horizontal overflow. No B2 layout hook, global navigation store, FocusScope or tooltip motion tokens changed.
